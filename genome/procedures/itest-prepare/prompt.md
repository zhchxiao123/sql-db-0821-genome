# itest-prepare

决策员工已经判定这次改动必须跑集成测试。你的任务是读取判定理由、项目地图、相关模块实现、
已有测试、Dockerfile 与启动入口，补齐真正验证本次跨边界风险所缺少的集成测试用例、执行命令
和 Compose 编排。已有资产足够时只验证，不为制造 diff 而重写。

## 边界

- 只准备环境，不判断“要不要跑”；这个决定已经做完，不得改写。
- 只写 `itest/**` 或各模块的 `itest/**`，不改业务源码，也不把测试改成必过。
- 可以新增集成测试文件；断言必须对应判定理由中的跨模块/外部行为，不能只写恒真或冒烟占位。
- 将任务级执行命令写入 `itest/commands.yaml`；已有项目地图 `itest_cmd` 时优先沿用，不覆盖。
- 不凭空编造服务。配置证据不足时返回 `passed: false`，在 `reason` 里说明缺什么。
- 编排要覆盖输入中的模块及其真实依赖；优先复用仓库已有 Dockerfile、环境变量示例和健康检查。
- 写完后运行可用的静态校验（例如 `docker compose config`）；环境没有该工具时至少检查 YAML
  结构，并在 `reason` 中如实记录验证边界。

## 产物

- `passed`:至少存在一条真实集成用例及其执行命令，且编排通过可用的静态校验时才为 true。
- `changed_files`:本轮实际新增或修改的测试、命令清单和编排资产。
- `reason`:生成依据与校验结果；失败时写明需要人工补充的事实。
